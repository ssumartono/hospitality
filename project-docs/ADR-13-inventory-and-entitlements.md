# ADR-13 — Inventori, preview kamar dan entitlement

1 November 2026. Target B03.1/B03.2/B16.1; bukan approval produksi.

Dependency B01/B02 sudah mempunyai implementasi dan evidence auth/MFA/staf/RLS untuk domain yang tersedia. Story tetap IN_PROGRESS sampai review/acceptance terkait lengkap; AC lintas modul bukan alasan menandai seluruh gate lulus. Irisan inventori memakai authorizer ini. Private upload/scanner, kontrak dan finance yang belum selesai tidak di-bypass.

Lokasi yang sudah dibuat dipertahankan. Kode lokasi, lantai dan segment ditambahkan sebagai konfigurasi draft nullable; operator melengkapinya sebelum menambah kamar. Alamat/foto/rekening/harga tetap tidak dikarang. Owner mengubah profil lokasi; Manager mengelola tipe/kamar hanya pada lokasi yang diizinkan, Ops mengisi checklist lokasi, Finance hanya baca informasi fisik. Tipe kamar diberi propertyId supaya perubahan tidak menembus scope lokasi. Ini perincian request baseline yang belum menetapkan scope tipe. Versi default tipe immutable; kamar menyimpan snapshot versi/capacity/facilities, edit default tidak mengubah kamar lama. Update eksplisit kamar memakai optimistic version.

Generator sequence mempertahankan konsep prefix/startNumber/count/floor/typeId baseline, ditambah mode pilot/manual. Preview disimpan server dengan checksum, snapshot tipe/profil lokasi, actor, expiry teknis 15 menit. Commit memerlukan konfirmasi kode/denah, idempotency key, snapshot masih berlaku, kuota dan kode unik. Semuanya atomik. Seed pilot adalah contoh 101–106/201–206, enam per lantai; dapat disesuaikan sebelum konfirmasi, bukan denah yang dianggap nyata. Seed pilot diberi source key unik per lokasi agar pengulangan tidak menggandakan data. Seluruh kamar baru inspection, checklist belum diperiksa. Checklist lengkap tidak otomatis ready: transition ready/arsip/blokir baru dapat diaktifkan setelah alokasi/presence/blocker terkait terintegrasi (B07.1/B03.3/B13.3). Tidak mengklaim vacancy dari checklist.

Harga/paket komersial dan durasi trial belum disepakati. Database plan/entitlement menyimpan snapshot kuota dan state; user tidak dapat menaikkan kuotanya lewat API. Fixture terpisah TEST_ONLY menyediakan paket lokal 100 kamar/10 lokasi/100 staf, tanpa harga atau expiry komersial. Provisioning fixture hanya eksplisit pada database localhost development/test. Paket development ditolak di NODE_ENV=production; tanpa konfigurasi plan nyata acquisition ditolak. Nilai fixture bukan keputusan bisnis atau batas produk 12 kamar. Existing data tidak dihapus bila kuota terlampaui.

Kuota menghitung kamar/lokasi nonarsip dan membership aktif, termasuk Owner, dalam organisasi penuh. Lock row entitlement dan trigger database mencegah concurrent create/bulk/restore/accept melewati limit. Role lokasi tidak boleh mengurangi angka usage yang dipakai quota check. Restricted/cancelled/expiry menolak acquisition baru, tetapi membaca/mengedit informasi lama, checklist dan mencabut akses tetap tersedia. B16.2 admin aktivasi/expiry scheduler/downgrade UI belum dibangun; tidak ada flag paid palsu. Default plan baru berasal dari konfigurasi deployment yang diprovision administrator, tidak dari body user.

Kontrak implementasi inventori ditulis api/inventory.openapi.json sebelum frontend. Bukti AC-01/16 untuk slice ini dipisah dari acceptance booking/checkout penuh. Seed via API membutuhkan kredensial/mfa milik operator sendiri, explicit confirmation dan key idempoten; tidak dibuat akun/password default, tidak menyamar sebagai Owner lewat fixture produksi.
